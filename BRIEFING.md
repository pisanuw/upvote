# Briefing

- Purpose: UpvoteMe — private, unlisted topic threads with comments, attachments, and voting. Next.js App Router + TypeScript, Prisma + Supabase Postgres, NextAuth (Auth.js). Live at upvoteme.hintwise.org (upvoteme.netlify.app 301s there since 10 Nov 2026).
- Current scope: Maintain the public repo (github.com/pisanuw/upvote). 2026-06-10 hardening pass complete: secret hygiene, fail-closed security, CI gates, dependency advisories, history/presentation. Licensed MIT.
- Key decisions:
  - `.env.asc` (RSA-4096 / AES-256-OCB encrypted secrets bundle) is intentionally committed as an encrypted backup; GPG private key A4C59E8DCB190977 is held securely. Plaintext secrets never go in git — they live in the gitignored `.env` and in Netlify env settings.
  - Secret scanning + commit-message format enforced via `.githooks/` (pre-commit gitleaks, commit-msg Conventional Commits); activate per clone with `git config core.hooksPath .githooks`.
  - Conventional Commits required for all commits (documented in AGENTS.md).
  - CI (.github/workflows/ci.yml) gates on push+PR: npm ci, lint, typecheck, test, build. Node 20. Build step uses placeholder env vars since all data routes are dynamic (no DB at build).
  - Secrets compared in constant time (src/lib/safe-equal.ts) for CRON_SECRET and SUPERADMIN_SECRET.
  - Rate limiter (src/lib/rate-limit.ts) is best-effort in-memory only; NOT effective on serverless. The one durable limit is sign-in by emailed code (src/lib/sign-in-code-store.ts: rows in VerificationToken).
  - next pinned at 16.4.6, eslint-config-next equal to it. Overrides: fast-uri ^3.1.2, and nodemailer for next-auth (next-auth 4.24.x declares peer nodemailer ^7; the app runs ^10.6.0 because the magic-link address reaches nodemailer's address parser, quadratic before 10.0.6). `npm audit --omit=dev` clean on 2026-11-19.
  - prisma.config.ts reads DATABASE_URL tolerantly so `prisma generate` / `npm install` work with zero config on a fresh clone.
  - The Supabase Postgres DB is SHARED with a second app (a learning/tutoring platform; ~19 extra tables in the public schema). DB-wide operations affect that app, so scope any DB change to UpvoteMe's 8 tables. All 8 already have RLS enabled (deny-all; backend bypasses via the Prisma `postgres` owner role + the service-role key). No `_prisma_migrations` table (schema applied via `prisma db push` + manual SQL in prisma/migrations/manual/).
  - Google sign-in goes through the shared HintWise Supabase project (auth.hintwise.org) since 10 Nov 2026: a NextAuth OAuth provider `supabase` (src/lib/supabase-auth.ts), PKCE, sessions still NextAuth database sessions. Only Google-verified emails sign in; existing users are linked by email. No Supabase tokens are stored. Rollback: NEXT_PUBLIC_GOOGLE_AUTH_VIA=direct (README).
  - Email sign-in sends a 6-digit code, not a link, since 20 Nov 2026 (the owner's link failed at UW, most likely a mail scanner used it up). Still NextAuth's Email provider: an adapter wrapper binds each code to its address and to the asking browser's httpOnly cookie (no lockout by outsiders; codes work only in that browser) and enforces 5 wrong codes per code; per address 1 code/min, 6/hour, 12/day; per client IP (x-nf-client-connection-ip, IPv6 by /64) 3/hour and 4/day per address, 300/hour and 1000/day in all (off, with one logged warning, when the header is missing); a browser that signed in as the address (signed year-long known-browser cookie, HMAC with NEXTAUTH_SECRET/AUTH_SECRET) has its own 3/hour and 6/day and skips the other limits. Numbers: CODE_LIMITS in src/lib/sign-in-code.ts. Its rows live under "Sign-in code…" identifiers; outside them it deletes only rows a link sent before codes left for the same address (64-hex token, expiring within a day). No schema change.
- Non-goals (for now):
  - Not migrating to next-auth v5 (a major migration). The v4 advisories were fixed within 4.x (4.24.15, 2026-11-19).
  - No git history rewrite (single squashed Initial commit left as-is; work stays incremental going forward).
  - No durable/shared rate limiting beyond sign-in codes until a real need arises.
